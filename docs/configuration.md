# Configuration

The server reads only `~/.config/ad-linux-tv/config.yaml` by default. Keep it mode 0600. New installations start with PIN access disabled. TV System and phone Menu → Settings can enable or replace a four-digit PIN; only its PBKDF2-HMAC-SHA256 verifier (310,000 rounds) is stored in config. Older configurations keep their `auth.require_pin` value (or the legacy default `true`). The schema also includes `bind` (IP), `port` (fixed at 8765), `page_size` (1–100), services with unique IDs and HTTPS URLs, and optional `proxy`. The initial service set is VK Видео, КиноПоиск, Яндекс Музыка, YouTube, KION, and Браузер (`https://ya.ru/`).

Any device on the trusted private network can open the remote while PIN is off; the server still issues a session cookie and checks CSRF and Origin. Changing the PIN mode or code in Settings invalidates prior sessions immediately. The Beelink currently uses PIN-free mode. Proxy choices affect only its TV Firefox profile: system, none, or a specified HTTP/SOCKS5 host and port. A saved proxy change needs the offered TV-session restart. The existing local Xray `127.0.0.1:1081` profile is preserved until changed.

Bridge endpoint port 8765 is fixed in the Firefox extension and must remain synchronized. Client responses never include auth data. HTTP has no TLS: use only on a trusted private LAN; do not forward ports. Session cookies are HttpOnly and SameSite=Strict but intentionally omit Secure so they work over the documented HTTP LAN. The server ignores forwarded IP headers and rejects local DNS-rebinding Host values. For a loopback-launched TV page, the QR address uses a configured LAN bind IP or the OS-selected private route address; if none is available, it reports no reachable LAN address. The launcher checks the address every five seconds and refreshes the QR when it changes, including after DHCP renewal or switching between Ethernet and Wi-Fi.
