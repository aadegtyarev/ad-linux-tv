# Surface contract: TV launcher

## Boundary and consumers
The browser-rendered home page and Firefox bridge provide TV service selection and browser-tab control. The Python HTTP server owns service catalogue, command queue, and status; launcher clients are unauthenticated on the TV-side local page.

## Inputs, outputs, and flows
- `/` renders configured services, an adaptive grid, page indicator, phone QR/address, a pairing PIN or “PIN не нужен” on the local TV screen according to configuration, and bridge/command status. A small System button is always visible in the upper right for pointer clicks and offers a confirmed switch to KDE in the dedicated kiosk session. The same QR also opens the ordinary browser's compact Android0.2.5 APK invitation before PIN and on MAIN after PIN-free/session-restored entry; browser use and native scanner pairing remain independent. The [installed delivery record](../../verification/android-apk-download-2026-10-27.md) verifies HTTP bytes, not physical camera/phone acceptance. The service set may include a Browser tile opening Yandex search as an ordinary managed Firefox tab. An optional validated color from each service configuration gives its tile a branded accent on a dark, readable background; tiles without color stay neutral. The System menu offers TV audio output, volume and mute controls, a three-note chime and the display timer. The phone Menu can open TV System via the launcher F8 shortcut after Home.
- TV System uses two compact columns at the target 1360×768 output and includes PIN mode/code, a cursor magnifier toggle, cursor acceleration 0–100, and TV Firefox proxy mode alongside sound, timer and KDE switch. The magnifier uses labwc's built-in cursor lens and starts off. Initial scale defaults2.5×, configurable1.25–5 in quarter steps. Saved and boot-applied values are separate; changing scale offers an explicit restart rather than actuating during viewing. Proxy changes offer a TV-session restart; PIN changes update the local pairing display immediately. Pointer controls remain available, and arrow/OK navigation includes the new controls while System is open. Shared «Вид сайтов» selects common settings or one site's override/inheritance; save/reset does not auto-restart or reload. The same collapsed «О программе» presents read-only server version/build. The [2026-10-27 installation](../../verification/settings-versions-2026-10-27.md) verifies shipped bytes/readiness, not physical navigation or site acceptance.
- `GET /api/services` supplies services, page size and advertised remote address; `/api/status` supplies bridge online, pending count and latest command failure. Polling refreshes every five seconds.
- Arrow keys move focus in the grid (wraps horizontally and vertically); arrows stay within the service grid and never move focus to System. Next/previous controls paginate. Bridge OK selects the focused service tile, even when System previously had pointer focus. In System, arrows move between controls, left/right adjust output or volume, and OK activates the focused control; leaving for KDE requires a second confirmation. Clicking a service tile queues `open`.
- Firefox bridge polls localhost port 8765 and executes open/home/back/refresh plus launcher navigation and bounded player-volume read/set commands; service selection opens a managed service tab. The installed signed 0.4.1 bridge closes other managed service tabs when switching services and closes every managed service tab on Home while leaving unmanaged Firefox tabs untouched. The accessible HTML-audio target 37% check was performed with signed 0.3.2 on 2026-10-25; it is historical evidence, not 0.4.1 service-playback acceptance.
- The phone-controlled pointer uses a white 72 px cursor in the dedicated TV session. Its appearance does not change pointer speed or site hit targets. TV System now offers separate output, Firefox-stream and accessible page-player target levels; the last two default to 100% and persist. The bridge applies the page-player target to accessible media; the local audio verification used signed 0.3.2. TV System also shows the current Firefox stream mute state and a separate saved mute/unmute target. The button works without an active stream and applies to new streams; it does not change output mute. Site-specific WebAudio or restricted frames may resist normalization. The touch sound panel keeps one output-volume slider.
- While a display timer is active, one layer-shell panel shows a clock and remaining time in the upper left, including above fullscreen video. This avoids bottom player controls and the upper-right touch toolbar. The semi-transparent background leaves text/icons opaque; normal time uses26px, expanded30px, with a taller hit area for TV distance. Hover/click enlarges and reveals Change/Cancel; Change presets and the automatic two-minute warning use this SAME panel. Collapse dismisses the warning only for that generation. It does not take keyboard focus or rebuild/show the whole panel each tick. The [2026-10-28 native repair](../../verification/timer-window-icon-2026-10-28.md) replaces a crashing themed GTK image with a text clock, without changing the image-loader sandbox or timer semantics. Real Wayland-output captures verify compact countdown and the expanded two-minute warning, followed by normal expiry/asleep; actual video-fullscreen placement, hover/button actuation and physical HDMI/CEC remain separate.
- A compact GTK layer-shell panel appears while a touchscreen is connected and no window is fullscreen. Its finger-sized left grab handle moves the panel within the display and stores the TV-user position. The Home icon sends Home through the loopback command route; Back and Forward send Firefox history shortcuts only when Firefox is the active TV window; the keyboard icon toggles Squeekboard through its session D-Bus API. Manual opening holds the keyboard visible through transient site focus loss until dismissal with the keyboard icon, Home, fullscreen, or touchscreen removal. The sound icon opens a temporary output-volume slider backed by the local audio API and remains open during a touch drag. The Timer icon opens presets and a remaining-time status over the current video; it leaves the Firefox tab unchanged. The controls hide when a window enters fullscreen or the touchscreen is disconnected. The Squeekboard language key cycles `EN→RU` and `RU→EN` through a labwc F12 binding, without the tiny popup; physical touch switching was confirmed on Beelink. Firefox's dedicated TV profile hides browser chrome until the address field receives focus; the normal maximized window still allows Squeekboard above page content. It requires no extension permission change.

## Installed bridge capabilities and tile-open repair
Signed 0.4.1 provides bounded managed-HTML status/play/pause/seek and declarative service view, not an arbitrary browser-script interface. Version1 reports have sequence/send-time/three-second freshness; legacy 0.3.2 sends no such capability, so unsupported media operations are not queued. Capability freshness is not authentication or proof of playback. View mode uses a fixed mobile HTTP UA plus independently scoped per-tab zoom. Managed startup prepares the dedicated profile for per-tab scope, including inherited common settings; a full Firefox restart applies that preference while preserving original lines. No zoom setter targets unmanaged tabs and there is no per-origin fallback.

Before first service navigation, 0.4.1 performs a bounded `getZoomSettings`, rechecks tab ownership, validates automatic/per-tab settings, then applies `setZoom`. It never calls the failing `setZoomSettings`. Getter failure or incompatible scope prevents the write; dispatched write uncertainty and no replay remain unchanged. Header isolation and ownership/generation fencing remain in force. The signed payload retained 0.4.0's ID and permissions. An actual served Browser-tile click returned202, drained the queue without failure and received operator confirmation. This accepts the tile-open repair only; protected/live/ambiguous media, mobile layout, playback, seek and DRM remain unqualified. See the [verification record](../../verification/tile-open-zoom-2026-10-26.md) and [bridge protocol](../../bridge-protocol.md).

## Shared timer and power boundary
Immediate phone display sleep reuses the timer's bounded asynchronous managed-media pause, verified-silence and generation guards. A newer timer/wake/input invalidates stale sleep work; unknown/active audio leaves HDMI lit. Wake does not resume media or prove the physical TV woke. The optional existing CEC path is directed wake only, with manual-TV-remote fallback; no TV System whole-host shutdown control or generic wake provisioning is added. Whole-host confirmation belongs to the authenticated phone surface, not the unauthenticated launcher. See [delivery evidence](../../verification/remote-power-2026-10-26.md).

## Guarantees, failures, and security
- Pagination and focus are adaptive to configured page size and responsive CSS grid. The launcher refreshes the advertised LAN address and QR when the route address changes. Opening a service shows a spinner while the bridge accepts the command, then a retry hint if the launcher remains visible; a third-party page may instead show Firefox's own loading or error page. Status displays bridge offline, pending commands, and last failed/uncertain outcome alongside pending state.
- Queue is bounded (128); browser lease/poll and acknowledgements expose failures. Extension command execution is at-most-once after persisted execution claim; interruption in claim/effect/ack window can lose an action and report uncertain. Completed effect is not repeated on lost acknowledgement. Deduplication ledger is bounded (256); tab ownership survives event-page unload, not browser restart or extension reload/update/disable.
- Launcher is served over local HTTP; remote control constraints are in [phone remote](phone-remote.md). Firefox bridge uses the localhost host permission and bridge header, not a general remote browser API. Authenticated phone text entry uses the compositor's virtual keyboard protocol; it does not change extension permissions.
- `POST /api/system/kde` is available only to the kiosk launcher over loopback with exact `127.0.0.1:<port>` Host and matching Origin. It starts a narrowly authorized systemd switch unit. LAN clients cannot call it directly.
- `GET /api/local-pin` reports that a PIN is not required in PIN-free mode, or reads the configured mode-0600 PIN file in PIN mode. It is available only in the kiosk, with loopback source, exact localhost Host and a launcher request header. LAN clients cannot retrieve it; the response is not cached.

## Non-goals and verification
No guarantee of arrows/OK on third-party pages, service playback/DRM, or exactly-once browser actions. Automated source/tests cover layout, focus selection, commands, status and local-only PIN boundary. On Beelink, HDMI rendering and reboot, Browser/YouTube opening, bridge persistence across Firefox restarts, the System-to-KDE switch, Ethernet/Wi-Fi address failover and an audible HDMI test sound have been checked. Real-phone control, a fresh DHCP lease, no-HDMI fallback and playback/DRM remain target checks.
