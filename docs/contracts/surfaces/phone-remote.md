# Surface contract: phone remote

## Boundary and consumers
The `/remote` web UI on a phone submits browser commands to the TV's Python HTTP service. The service queues commands for the Firefox bridge. This is trusted-LAN HTTP, not a secure Internet-facing remote.

## Inputs, outputs, and flow
- The phone Menu opens a Settings page for PIN and Firefox proxy. A magnifier button sits beside volume directly below the touchpad and toggles the TV's built-in cursor lens. Authenticated reads and writes use the existing `/api/remote-ws` channel and same session/Origin/CSRF checks; no new live transport is created. The phone never receives the PIN, verifier or salt. Saving a PIN change invalidates its current session, so the page reloads into the new login mode. A proxy change offers a TV-session restart.
- By default, user submits PIN to `POST /api/login`; the phone field has a show/hide eye control and the Beelink uses a four-digit numeric code displayed only on the local TV screen. With `auth.require_pin: false`, a private-network phone obtains a session without PIN from `GET /api/session`; `POST /api/login` is disabled. Either path sets an HttpOnly, SameSite=Strict, 14-day session cookie and returns a CSRF token. Service selection comes from `/api/services`; commands post JSON to `/api/command` with CSRF header.
- Queued commands: `open` with configured service ID, `home`, `back`, `refresh`, plus legacy launcher-only `up`, `down`, `left`, `right`, `ok`. The redesigned phone sends directional/OK keys through `/api/input` and receives 200 on success. Accepted queued commands return 202; malformed/unknown commands 400, unauthenticated or invalid-origin requests 403, rate limited login 429, full queue 503, oversized payload 413.
- `GET /api/session` returns the CSRF token for a valid cookie to the same-origin phone page, allowing it to reopen without PIN. In PIN-free mode, it creates a session for a private-network source when no valid cookie exists. TV sessions are saved in a private mode-0600 TV-user file and survive service restarts for up to 14 days; changing the PIN verifier or authentication mode invalidates saved sessions.
- Authenticated `POST /api/input` uses the same session, Origin and CSRF checks, even for a loopback client. It accepts exactly one printable UTF-8 `text` field (1–512 characters) or one allowlisted key (`enter`, `backspace`, `tab`, `shift-tab`, `address`, `escape`, `browser-back`, `browser-forward`, `up`, `down`, `left`, `right`, `ok`, `system`, `video-fullscreen`). The TV process sends it through labwc's virtual keyboard protocol to the focused Firefox field; input is never queued, logged, stored, or returned. It returns 200 on success, 400 for invalid input, 403 without authorization or outside the TV session, and 503 if keyboard injection is unavailable. The phone form uses Android/iOS's native keyboard and clears submitted text.
- Authenticated `POST /api/pointer` uses the same session, Origin and CSRF checks as `/api/input`. It accepts exactly one bounded move (`dx`, `dy`), click, or scroll action and invokes labwc virtual-pointer commands only while Firefox is active. The virtual cursor is global and can click a focusless TV overlay under it. Invalid values return 400; unavailable pointer or inactive Firefox returns 503. The service stores no pointer trace.
- Authenticated `GET /api/audio` reports available TV-user sinks, selected output, volume, mute, current Firefox stream level and mute if present, and saved Firefox level/mute and page-player targets. `POST /api/audio` with Origin, session and CSRF selects a listed sink, moves current TV audio streams, sets output volume within 0–100%, toggles output mute or current Firefox stream mute independently, or saves a bounded Firefox/page-player target. The phone Settings page shows all three levels; the touchpad retains one output-volume control. The saved Firefox target applies to new streams. Signed bridge 0.3.2 applies the page-player target to accessible media; a local HTML-audio test passed. The phone Settings page exposes a saved Firefox stream mute target even when no stream exists; the server applies it to active and future streams. Site WebAudio and restricted frames may resist media normalization. Errors leave browser commands available.
- Authenticated `GET` and `POST /api/display-timer` report or set an Off, 15, 30, 60, 90 or 120-minute display timer. Status includes a nonsecret generation identifier, so a dismissed two-minute TV warning stays dismissed only for that countdown. The phone's main Timer button shows a small remaining-time badge while active. The phone session, same-origin and CSRF checks apply. At expiry the server pauses managed playing media before powering off HDMI; if pause or other audio cannot be verified silent, HDMI remains lit and the UI reports a reason. Any phone action wakes a dark screen without resuming playback.
- `/api/status` reports bridge online, pending count, latest failed/uncertain result and the OS-preferred LAN remote URL. The phone receives the same status through its authenticated WebSocket. It attempts to move to a changed private IPv4 URL while its old connection still works; an abrupt loss still requires scanning the current QR. UI polls each second over the socket, presents pending/failure/connection-loss status in a fixed header indicator without moving controls and forces relogin after 401/403.
- The paired phone opens a one-screen remote with Home, Timer, a large touchpad with four edge arrows, output volume/mute and Text. Buttons show touch feedback immediately. Edge-arrow taps inject virtual keyboard keys into the active Firefox window without switching tabs. Dragging anywhere on the touchpad moves the TV pointer; a saved 0–100 cursor-acceleration setting keeps slow motion precise and increases fast travel, with zero restoring the former constant mapping. The user confirmed the faster curve on a real phone. After arrow or Tab navigation a pad tap sends Enter to the focused element; after a cursor drag or scroll a pad tap clicks at the cursor. The center hint changes between «Выбрать» and «Клик» without becoming a separate button. Two-finger swipes scroll with two visible contact indicators. The phone sends all live requests through one authenticated WebSocket at `/api/remote-ws`; the server processes them in socket order. Up to three pointer messages may be awaiting replies while excess movement is coalesced; click and scroll wait for preceding movement. On connection loss, uncertain actions are not replayed automatically and the saved session reconnects on the next request. HTTP remains for page/assets, QR and session/login bootstrap; legacy control routes remain for the TV launcher and bridge. Back is the leftmost button beneath the touchpad, followed by Shift+Tab, Tab and Enter; the latter three move and activate browser focus. Pointer actions work for desktop sites that do not handle keyboard arrows. Text opens a second screen using the phone native keyboard. Timer opens a dedicated preset screen on the phone without changing the TV video tab. Menu contains service launch, URL entry, Forward, Refresh, audio output, a test chime, Tab/Shift+Tab, an Open System action and a QR screen for a second phone. This QR contains only the current LAN remote URL; its text address is also displayed. Open System returns to launcher, waits for Home to complete, then sends the authenticated F8 shortcut. Back/Forward use authenticated TV-session Firefox history shortcuts only while Firefox is active. The URL form opens the configured Browser service, waits for the bridge queue to settle, then focuses Firefox address and sends the HTTP(S) URL through authenticated input.

## Security and privacy
- Private/loopback source checks apply to `POST /api/login`, `GET /api/session` and command POSTs. In PIN-free mode, anyone on the reachable private network can open the remote; same-origin cookies and CSRF still protect command requests from other websites. Publicly reachable GET surfaces include `/`, `/remote`, `/api/services`, `/api/status`, `/health`, `/api/qr`, and static UI assets: any network source able to reach the bound listener can request them. These return UI, the configured service catalogue/advertised address, QR data, or operational status; they do not return the PIN or session/CSRF secrets. `GET /api/audio` also requires a paired session except for the exact local TV kiosk. `GET /api/local-pin` is the exception: it is available only to the local TV launcher, with loopback source, exact `127.0.0.1:<port>` Host, a launcher request header and kiosk PIN-file configuration. It is denied over LAN and marked no-store.
- Phone login and command POSTs require a private/loopback client source. Phone POSTs also require HTTP Origin to equal Host, a syntactically valid Host, and (for commands) a valid session and CSRF token. This does not verify that the Host address belongs to the server. For loopback local UI POSTs, Host must parse as localhost or a loopback IP. Firefox bridge poll/ack additionally require loopback source, exact `127.0.0.1:<listener-port>` Host, and the bridge header/value.
- The WebSocket upgrade requires a private source, same-origin `Origin`/`Host`, valid session cookie and CSRF token supplied in its subprotocol header. Messages have bounded size, use an allowlisted method/path pair, and recheck session authorization. A failed handshake or invalid frame closes the channel without executing an action.
- No TLS: use only a trusted private LAN; do not port-forward. PIN, search text, and passwords typed on the phone traverse LAN HTTP. Session cookie deliberately lacks Secure for LAN HTTP. The PIN is never returned to LAN clients; config contains a salted PBKDF2 verifier, while the dedicated TV user keeps a private mode-0600 PIN file for local display and a separate mode-0600 session file. Client status uses fixed outcome/reason codes and excludes URLs, PINs, typed text, and exception text. HTTP access logs are suppressed.
- Local TV launcher command submission is intentionally separate from phone authentication.

## Failure, limits, and verification
The in-memory queue is FIFO and bounded to 128; status reports extension offline after 30 seconds, pending commands, and latest failure for up to 300 seconds. A later success does not clear the last failure; a newer failure replaces it. Remote UI displays pending and failure concurrently. Extension execution is at-most-once after claim and may be uncertain/lost on interruption; see [TV launcher](tv-launcher.md).

Automated tests verify authentication, CSRF/origin/security, queue and response semantics. On Beelink, the LAN remote and QR returned 200, authenticated text reached Firefox in Cyrillic, the managed Browser tab accepted a direct URL with the TV toolbar normally hidden, and Ethernet-to-Wi-Fi failover changed the advertised address and QR in both directions. The user confirmed smooth cursor motion and scrolling over the WebSocket on a real phone. Second-phone QR pairing and a fresh DHCP lease remain to be checked.

## Non-goals and related contracts
Arrows and OK send keys to the active Firefox page; site-specific focus/navigation behavior is not guaranteed. The HTTP LAN page is not an installable PWA; a stable hostname and trusted HTTPS setup are separate work. No TLS, Internet exposure, exact-once command guarantee, or service/DRM guarantee.
