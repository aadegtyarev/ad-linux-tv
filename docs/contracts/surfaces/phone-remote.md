# Surface contract: phone remote

## Boundary and consumers
The `/remote` web UI on a phone submits browser commands to the TV's Python HTTP service. The service queues commands for the Firefox bridge. This is trusted-LAN HTTP, not a secure Internet-facing remote. The optional [Android shell](android-remote.md) adds discovery and isolated multi-center selection; it loads this same server UI.

## Inputs, outputs, and flow
- The phone Menu opens a Settings page for PIN, Firefox proxy and Firefox interface language («Язык браузера»). A magnifier button sits beside volume directly below the touchpad and toggles the TV's built-in cursor lens. Authenticated reads and writes use the existing `/api/remote-ws` channel and same session/Origin/CSRF checks; no new live transport is created. The phone never receives the PIN, verifier or salt. Saving a PIN change invalidates its current session, so the page reloads into the new login mode. Proxy and initial magnifier-scale changes offer a shared explicit TV-session restart. The scale is saved in quarter steps1.25–5/default2.5; saving never interrupts playback and UI distinguishes desired from boot-applied scale.
- By default, user submits PIN to `POST /api/login`; the phone field has a show/hide eye control and the reference TV uses a four-digit numeric code displayed only on the local TV screen. With `auth.require_pin: false`, a private-network phone obtains a session without PIN from `GET /api/session`; `POST /api/login` is disabled. Either path sets an HttpOnly, SameSite=Strict, 14-day session cookie and returns a CSRF token. The TV service catalogue remains available at `/api/services`; legacy command clients post JSON to `/api/command` with CSRF header. The configured-site selector in Settings scopes view editing only; it does not launch services.
- Queued commands: `open` with configured service ID, `home`, `back`, `refresh`, `fullscreen` (only while the bridge reports `video_fullscreen_v1`, otherwise 409), plus legacy launcher-only `up`, `down`, `left`, `right`, `ok`. The redesigned phone sends directional/OK keys through `/api/input` and receives 200 on success. Accepted queued commands return 202; malformed/unknown commands 400, unauthenticated or invalid-origin requests 403, rate limited login 429, full queue 503, oversized payload 413.
- `GET /api/session` returns the CSRF token for a valid cookie to the same-origin phone page, allowing it to reopen without PIN. In PIN-free mode, it creates a session for a private-network source when no valid cookie exists. TV sessions are saved in a private mode-0600 TV-user file and survive service restarts for up to 14 days; changing the PIN verifier or authentication mode invalidates saved sessions.
- Authenticated `POST /api/input` uses the same session, Origin and CSRF checks, even for a loopback client. It accepts exactly one printable UTF-8 `text` field (1–512 characters) or one allowlisted key (`enter`, `backspace`, `tab`, `shift-tab`, `address`, `escape`, `browser-back`, `browser-forward`, `up`, `down`, `left`, `right`, `ok`, `system`, `video-fullscreen`). The TV process sends it through labwc's virtual keyboard protocol to the focused Firefox field; input is never queued, logged, stored, or returned. It returns 200 on success, 400 for invalid input, 403 without authorization or outside the TV session, and 503 if keyboard injection is unavailable. The phone form uses Android/iOS's native keyboard and clears submitted text.
- Authenticated `POST /api/pointer` uses the same session, Origin and CSRF checks as `/api/input`. It accepts exactly one bounded move (`dx`, `dy`), click, or scroll action and invokes labwc virtual-pointer commands only while Firefox is active. The virtual cursor is global and can click a focusless TV overlay under it. Invalid values return 400; unavailable pointer or inactive Firefox returns 503. The service stores no pointer trace.
- Authenticated `GET /api/audio` reports available TV-user sinks, selected output, volume, mute, current Firefox stream level and mute if present, and saved Firefox level/mute and page-player targets. `POST /api/audio` with Origin, session and CSRF selects a listed sink, moves current TV audio streams, sets output volume within 0–100%, toggles output mute or current Firefox stream mute independently, or saves a bounded Firefox/page-player target. Phone Menu → Sound shows all three levels, output and Firefox mute controls; the touchpad retains one output-volume control with a clear Вкл/Выкл/? state. Audio is refreshed from the server and an unavailable read disables the main mute button rather than leaving stale state. The saved Firefox target applies to new streams. Signed bridge 0.3.2 applies the page-player target to accessible media; a local HTML-audio test passed. The phone Settings page exposes a saved Firefox stream mute target even when no stream exists; the server applies it to active and future streams. Site WebAudio and restricted frames may resist media normalization. Errors leave browser commands available.
- Authenticated `GET` and `POST /api/display-timer` report or set an Off, 15, 30, 60, 90 or 120-minute display timer. Status includes a nonsecret generation identifier, so a dismissed two-minute TV warning stays dismissed only for that countdown. The phone's main Timer button shows a small remaining-time badge while active. The phone session, same-origin and CSRF checks apply. At expiry the server pauses managed playing media before powering off HDMI; if pause or other audio cannot be verified silent, HDMI remains lit and the UI reports a reason. Ordinary phone input restores the output without resuming playback; the power gesture/dialog is excluded from generic pointerdown wake. Output-on is not proof that the physical TV woke.
- `/api/status` reports bridge online, pending count, latest failed/uncertain result and the OS-preferred LAN remote URL. The phone receives the same status through its authenticated WebSocket. An unbound legacy browser page attempts to move to a changed private IPv4 URL while its old connection still works; an abrupt loss still requires the current address/QR. A device-bound Android page never follows this hint or strips its identity fragment: a new origin requires explicit selection and a separate profile. UI polls each second over the socket, presents pending/failure/connection-loss status in a header indicator and readable feedback and forces relogin after 401/403.
- The paired phone opens a large-target remote that scrolls on short screens or large fonts, with Home, Timer, a large touchpad with four edge arrows, output volume/mute and Text. Buttons show touch feedback immediately. Edge-arrow taps inject virtual keyboard keys into the active Firefox window without switching tabs. Dragging anywhere on the touchpad moves the TV pointer; a saved 0–100 cursor-acceleration setting keeps slow motion precise and increases fast travel, with zero restoring the former constant mapping. The user confirmed the faster curve on a real phone. After arrow or Tab navigation a pad tap sends Enter to the focused element; after a cursor drag or scroll a pad tap clicks at the cursor. The center hint changes between «Выбрать» and «Клик» without becoming a separate button. Two-finger swipes scroll vertically, horizontally or diagonally with two visible contact indicators. Pointer scroll accepts strict integers `scroll` and optional legacy-compatible `scroll_x`, each within ±64 and not both zero. Ordered/coalesced delivery and cancellation prevent a gesture becoming an accidental click. The phone sends all live requests through one authenticated WebSocket at `/api/remote-ws`; the server processes them in socket order. Up to three pointer messages may be awaiting replies while excess movement is coalesced; click and scroll wait for preceding movement. On connection loss, uncertain actions are not replayed automatically and the saved session reconnects on the next request. HTTP remains for page/assets, QR and session/login bootstrap; legacy control routes remain for the TV launcher and bridge. Back is the leftmost button beneath the touchpad, followed by Shift+Tab, Tab and Enter; the latter three move and activate browser focus. Pointer actions work for desktop sites that do not handle keyboard arrows. **⛶ Экран** in the bottom row sends `fullscreen`: the bridge fullscreens the largest visible video's player (playing preferred) or leaves fullscreen; nothing becomes fullscreen automatically, no video means `no_media`, and a 409 says the TV bridge needs updating. Text opens an inline field above the footer using the phone native keyboard. Successful submission clears/closes it; duplicate submits are fenced and failed/uncertain submits are not replayed. Timer opens a dedicated preset screen on the phone without changing the TV video tab. Menu contains actual settings: audio output/levels, a test chime, access/proxy/pointer/magnifier parameters and a QR screen for a second phone. It does not contain service launching, website-address entry, Forward/Refresh, duplicate Tab banks or Open System. Those server commands remain compatible; removing a phone control does not remove an endpoint. A compact media panel below the touchpad shows a single horizontally scrollable title, fixed SVG controls, elapsed/total time and seek. Previous/next and seek honor capabilities. Playback feedback uses a transient top overlay, with no reserved row or control movement. Resume/focus/pageshow/visibility reconciliation retires a stuck status GET without replaying playback/seek or reviving a retired selection; physical symptom resolution is not established by mocks. Media status comes from a background cache; a synchronous MPRIS POST can still delay ordered pointer traffic. With neither current MPRIS nor fresh managed-HTML media, the panel hides and the pad has more room. It never controls another app. The second-phone QR contains only the current LAN remote URL, also displayed as text. Back uses the authenticated TV-session history shortcut only while Firefox is active.

## Composition and feedback
The pre-redesign compact composition is restored: one primary action row, large pad, one focus row, compact media and a one-row volume/magnifier/text footer. Normal success/status feedback stays in the header or accessibility status, not new paragraphs above the pad. Error feedback is a temporary fixed overlay, not a layout row. Press feedback changes color without scaling the target. Timer badge space is reserved inside its original 48px button; active padding/icon sizing keeps countdown changes within that row. Home/Return anchors match across main, timer, menu, settings and QR pages. The inline-text close target is44px; remaining height primarily expands the pad, without a media-feedback spacer. A minimum pad/parent height prevents flex shrink from overlapping following controls; short screens may scroll. Synthetic geometry checks cover ordinary, pending and error states, not physical phone acceptance.

## Power control
A single ⏻ beside Timer requests explicit display sleep/wake through `/api/display-timer`, never a blind server toggle. Sleep cancels the countdown and reuses bounded asynchronous managed-media pause, verified silence and generation fencing. Active/unknown audio fails closed; wake does not resume playback. Optional existing CEC sends only a bounded directed wake, never standby/toggle/broadcast or provisioning. The out-of-flow hint tells the user to use the TV remote if no picture appears.

A 1.2-second hold opens whole-host confirmation, not shutdown or a subsequent tap. Motion/cancel, blur/visibility loss, auth expiry and native retirement cancel gestures/dialogs and fence late callbacks. Keyboard/context-menu access is supported. The warning covers all host tasks and physical-button restart; no phone WoL is provided.

Kiosk-only `/api/power` requires a session, same-origin and CSRF even on loopback. Strict prepare/shutdown DTOs issue a 20-second session-bound one-use challenge, with at most64 owners. Confirmation consumes it before the fixed actuator. Requested/uncertain dispatch latches, never retries or claims completed shutdown. The installed fixed unit and exact sudoers rule are not generic power privileges. [Delivery/source verification](../../verification/remote-power-2026-10-26.md) excludes real sleep/playback/CEC/shutdown acceptance.

## Shared site-view settings and read-only About
Phone and TV share «Вид сайтов»: «Все сайты» edits common mode/zoom; one configured site edits an override; «Как для всех сайтов» removes only that exception. Common omission/reset is desktop125. The same names/order/save/apply semantics are used on both surfaces, with no service-launching or arbitrary URL controls. Saving never automatically navigates/restarts/reloads; readiness determines whether an explicit restart is required before reopening a service. Generations protect newer drafts/acknowledged values, and matching acknowledgements update restart visibility and truthful feedback.

One collapsed «О программе» group shows media-center version/build from ordinary settings synchronization. A separate app row appears only when the public native constant is present; browser-only pages hide it. Missing/invalid/unavailable fields show «неизвестно», not guessed versions. Bounded typed values use textContent and wrap completely. Opening About and ordinary render recheck a late native constant locally. No extra API, polling, event bus, reload or action controls; metadata is not authentication.

The later [same-QR APK delivery](../../verification/android-apk-download-2026-10-27.md) is installed/read-only verified: server0.1.0/build8a, native0.2.5/code6 download200/full body hash. Its compact browser link appears before PIN and on MAIN after PIN-free/session-restored entry, not menu-only; native-bound Android pages instead give ordinary-camera/browser guidance. The [iOS presentation update](../../verification/ios-apk-invitation-2026-10-28.md) hides both Android invitations and Android-only guidance on iPhone/iPad/iPod, including desktop-style iPadOS hints (Macintosh/MacIntel with multitouch). Web controls/bootstrap/auth remain unchanged. Platform hints affect only visibility, never binding or authority; ordinary desktop/Android/unknown retain existing behavior, and direct APK GET is not User-Agent blocked. Link activation uses the existing no-wake exemption. Physical rendering/save/reopen/lifecycle and phone installation remain pending. Retain the [view](../features/site-view-overrides.md), [version](../features/remote-version-info.md) and [APK](../features/android-apk-download.md) contracts for those gates.

## Security and privacy
- The fixed APK GET is a nonsecret public binary, but separately requires private/loopback source and exact direct Host before file IO; no PIN/session/Origin is needed for ordinary navigation. It verifies the root-owned0444 single-link fixed artifact through one descriptor, limits transfers to2 with bounded deadlines, and otherwise fails closed503. No generic file server or relaxed control authority is introduced.
- Private/loopback source checks apply to `POST /api/login`, `GET /api/session` and command POSTs. In PIN-free mode, anyone on the reachable private network can open the remote; same-origin cookies and CSRF still protect command requests from other websites. Publicly reachable GET surfaces include `/`, `/remote`, `/api/services`, `/api/status`, `/health`, `/api/qr`, and static UI assets: any network source able to reach the bound listener can request them. These return UI, the configured service catalogue/advertised address, QR data, or operational status; they do not return the PIN or session/CSRF secrets. `GET /api/audio` also requires a paired session except for the exact local TV kiosk. `GET /api/local-pin` is the exception: it is available only to the local TV launcher, with loopback source, exact `127.0.0.1:<port>` Host, a launcher request header and kiosk PIN-file configuration. It is denied over LAN and marked no-store.
- Phone login and command POSTs require a private/loopback client source. Phone POSTs also require HTTP Origin to equal Host, a syntactically valid Host, and (for commands) a valid session and CSRF token. This does not verify that the Host address belongs to the server. For loopback local UI POSTs, Host must parse as localhost or a loopback IP. Firefox bridge poll/ack additionally require loopback source, exact `127.0.0.1:<listener-port>` Host, and the bridge header/value.
- The WebSocket upgrade requires a private source, same-origin `Origin`/`Host`, valid session cookie and CSRF token supplied in its subprotocol header. Messages have bounded size, use an allowlisted method/path pair, and recheck session authorization. A failed handshake or invalid frame closes the channel without executing an action. A per-connection token budget allows256burst/200frames per second, including control frames, alongside the30-second read deadline; exceeding it closes with policy code1008.
- No TLS: use only a trusted private LAN; do not port-forward. PIN, search text, and passwords typed on the phone traverse LAN HTTP. Session cookie deliberately lacks Secure for LAN HTTP. The PIN is never returned to LAN clients; config contains a salted PBKDF2 verifier, while the dedicated TV user keeps a private mode-0600 PIN file for local display and a separate mode-0600 session file. Client status uses fixed outcome/reason codes and excludes URLs, PINs, typed text, and exception text. HTTP access logs are suppressed.
- Local TV launcher command submission is intentionally separate from phone authentication.

## Failure, limits, and verification
The in-memory queue is FIFO and bounded to 128; status reports extension offline after 30 seconds, pending commands, and latest failure for up to 300 seconds. A later success does not clear the last failure; a newer failure replaces it. Remote UI displays pending and failure concurrently. Extension execution is at-most-once after claim and may be uncertain/lost on interruption; see [TV launcher](tv-launcher.md).

Automated tests verify authentication, CSRF/origin/security, queue and response semantics. On the reference TV, the LAN remote and QR returned 200, authenticated text reached Firefox in Cyrillic, the managed Browser tab accepted a direct URL with the TV toolbar normally hidden, and Ethernet-to-Wi-Fi failover changed the advertised address and QR in both directions. The user confirmed smooth cursor motion and scrolling over the WebSocket on a real phone. Second-phone QR pairing and a fresh DHCP lease remain to be checked.

## Media identity, feedback and installed bridge
Play/pause feedback is provisional until a fresh observed read confirms it; the underlying observed state is not changed by a command ACK. Duplicate actions are suppressed while pending, pending feedback respects reduced motion, and a five-second timeout does not retry. New clients send an optional32hex media_id precondition; changed targets reject with409, while legacy omission remains compatible and unfenced. Old GET/ACK/auth/body/lifecycle callbacks cannot confirm a new selection.

When MPRIS has inadequate timing, a fresh `html_media_v1` report from installed signed0.4.1 can provide managed-HTML timing and explicit play/pause/seek. Legacy signed0.3.2 does not provide it. The accepted0.4.1 tile-open repair does not qualify media timing/playback/seek; these remain separate checks. HTML actions require identity/deadline/actual seekable ranges, return202accepted rather than physical confirmation, and retain durable uncertainty/no replay. TTL, competing players, protected/live/inaccessible media or source changes can make it unavailable. See the [bridge protocol](../../bridge-protocol.md). Source/fake-DOM tests do not qualify actual Firefox/site behavior.

## Non-goals and related contracts
Arrows and OK send keys to the active Firefox page; site-specific focus/navigation behavior is not guaranteed. The HTTP LAN page is not an installable PWA; a stable hostname and trusted HTTPS setup are separate work. No TLS, Internet exposure, exact-once command guarantee, or service/DRM guarantee.
