# Surface contract: Linux operation

## Boundary and consumers
`install.sh`, `uninstall.sh`, CLI and graphical startup install/run/remove the application within the invoking user's session. Operators use the documented dry-run, install, update and removal flows. Kiosk-specific TV integration is staged separately from the existing KDE login.

## Paths and flows
- App, venv and run script: `~/.local/share/ad-linux-tv`. Persistent Firefox Snap profile and signed XPI: `~/snap/firefox/common/`. Configuration: `~/.config/ad-linux-tv/config.yaml`. Optional Plasma autostart: `~/.config/autostart/ad-linux-tv.desktop`.
- `./install.sh --dry-run` is the non-mutating default preview; actual installation requires explicit `./install.sh --install`. `--no-autostart` omits/removes the invoking user's Plasma autostart entry for a separately managed TV session. Installation creates a PIN-free configuration on first install, preserves existing config, uses a user venv, does not use sudo by default, and does not inspect personal browser state or register extensions unattended. Only managed proxy/view preference lines in the dedicated TV user.js are written when configured.
- `./uninstall.sh --dry-run` previews; `--remove` removes app/autostart and preserves config plus Firefox Snap profile/XPI. Update is backup config then rerun install.
- Release extension flow requires signed XPI and SHA256 supplied via `AD_LINUX_TV_XPI_URL` and `AD_LINUX_TV_XPI_SHA256`; installer verifies digest and opens XPI for explicit interactive Firefox confirmation. The reference TV target has signed bridge0.4.1 normally installed; its tile-open repair is operator-accepted, not service playback/seek qualification. Public release assets remain pending. Optional enterprise policy is a separate explicitly privileged target gate, not default installation.
- The dedicated kiosk targets any apt/snap Linux computer. `ops/kiosk/setup.sh` (run with sudo from the administrator account, or `AD_LINUX_TV_ADMIN`) creates `ad-tv`, installs labwc session packages, PipeWire, fonts, `python3-venv`, curl and Firefox Snap when missing, renders the administrator sudoers entry and installs `gui` into that account. `deploy.sh` installs the app for `ad-tv` and re-runs `configure-firefox.sh`. `boot-tv.sh` waits up to 30 s for a connected output before starting the kiosk. KDE is optional: without an SDDM unit, `/api/system/kde` returns 409, TV System hides the switch and `gui kde` reports it unavailable.
- `configure-firefox.sh` changes only the dedicated profile: it hides browser chrome, places the signed bridge from `common/ad-linux-tv-signed.xpi` into `extensions/` with `extensions.autoDisableScopes=0` (Firefox still enforces the AMO signature), and installs the language pack matching the installed Firefox version from releases.mozilla.org after `SHA256SUMS` verification. It does not write proxy preferences. Touch-panel glyphs use monochrome Noto Symbols fonts; themed images stay avoided inside the kiosk.
- In the kiosk, labwc, Squeekboard and a small GTK layer-shell touch overlay run Firefox in a maximized window with a dedicated Snap profile. A movable touch panel offers Home, browser Back/Forward, a keyboard toggle a temporary output-volume slider, display timer controls and a video fullscreen toggle over third-party pages; over fullscreen video only the fullscreen and volume buttons stay, and it hides when no touchscreen is connected. A separate GTK layer-shell timer badge stays visible when a countdown is active, even in fullscreen, and expands to an actionable warning at two minutes. An earlier badge was observed on the reference TV. The new unified translucent upper-left panel uses26/30px text, hover/click actions and in-place two-minute warning/presets; it avoids both player controls and the upper-right toolbar. The [2026-10-28 repair](../../verification/timer-window-icon-2026-10-28.md) atomically updates only the root-owned timer script: its clock is GTK text, avoiding the failing glycin/bwrap-backed themed image without weakening sandbox policy. Actual native-output captures verify countdown and automatic warning; the existing supervisor reloads it without a kiosk restart. Video-fullscreen/button/physical-HDMI checks remain separate. The touch panel's bounded position is stored privately for the TV user. The `ad-tv` Squeekboard layouts have a large EN/RU cycle key bound through labwc to rotate the TV user's GSettings input-source order; touch switching and persistence across a TV-session restart were confirmed on the reference TV. The TV profile hides Firefox browser chrome, while the phone remote can open a managed Browser tab and enter a direct HTTP(S) address. Home shows phone QR/address and either “PIN не нужен” or the current four-digit PIN read from a private file only by the local kiosk; a small System control opens the confirmed KDE switch. A separate root-owned systemd unit performs the switch; `ad-tv` may request that KDE switch unit, a restart of its own kiosk unit, or the separately confirmed fixed poweroff unit through narrowly scoped sudo rules. Console and SSH `gui` recovery remain available. The kiosk unit restarts the whole session after an unexpected browser/server exit, with a bounded systemd start limit.
- The dedicated labwc session overrides its default volume-up/down bindings to change the current software output through `wpctl` in 5% steps, capped at 100%; the bindings apply to standard media keys on keyboards and remotes. Other bindings, including the default mute binding, are unchanged. This configuration is not by itself proof of real-device or audible-output behavior.
- The supervised timer-overlay process also shows a separate, click-through, non-focusable volume bar above fullscreen windows for 2.5 seconds after a selected-output level change. A bounded background watcher observes PipeWire/Pulse changes without recording audio or media titles; an unavailable level is not displayed. Synthetic Wayland checks covered appearance, expiry, pointer pass-through and subscriber cleanup; the actual TV window mapped and unmapped in a no-capture probe, but physical-screen acceptance remains pending.
- The dedicated `ad-tv` labwc service binds F9 to its built-in cursor magnifier (initial default2.5×, saved1.25–5× quarter-step setting) and sets `XCURSOR_THEME=Oxygen_White` and `XCURSOR_SIZE=72`; reference TV setup installs the theme. This makes the phone-controlled pointer visible at TV distance without changing the KDE user's cursor settings. The target cursor size and click accuracy were confirmed after a TV-session restart.
- The dedicated Firefox profile proxy comes only from the `proxy` setting (system, none or custom HTTP/SOCKS5, with localhost/private LAN bypass); a local Xray is configured as custom HTTP `127.0.0.1:1081`. Firefox must restart to apply it; KDE's Firefox profile is not changed. Profiles that predate the setting and already point at `127.0.0.1:1081` are reported as that custom proxy. `ops/kiosk/select-audio.sh` honors the TV user's saved output if connected, otherwise prefers HDMI, then the available default.

## Derived startup configuration and Android
The own kiosk ExecStart invokes start-compositor.sh. It renders private XDG_RUNTIME_DIR/ad-linux-tv-labwc/rc.xml from the preserved /etc template, validated YAML scale and explicitly saved TV-session shortcuts, then starts labwc with that runtime directory. The template is not rewritten and no auth leaves the server config. Runtime metadata distinguishes requested from actually rendered shortcuts across a server-only restart. Saved slider or shortcut changes never change global labwc files or restart the session. Shortcut extensions of labwc's built-in defaults are admitted only for independently reviewed compositor defaults; unknown versions fail closed. Existing explicit matching bindings take precedence, including keysym aliases.

In the dedicated TV session, absent an explicit existing binding and where the XKB names exist, bare `XF86OK` and `XF86Select` default to one virtual Enter on release. When built-in labwc defaults are enabled, these bindings are added only for a reviewed version; unknown defaults are left untouched. Ordinary Enter and arrows are untouched. The setting is shared across devices, not a per-remote mapping; the existing externally administered UR02 hwdb rule is neither removed nor required for symbols already exposed by XKB. A synthetic headless labwc test on the reference TV covered these symbols, standard Enter/arrows, held input and preserved custom aliases. Physical OK/SELECT behavior, other systems and shortcut-inhibited applications remain unverified. The reference UR02 already produces Enter because of its external hwdb rule, so its confirmed OK operation does not test the new session-level path; that rule is not removed or changed. Six optional user-selected extra keys likewise use fixed labwc actions and no evdev grab, uinput broker or BPF. Extra volume keys use the existing 5% `wpctl` action and repeat while held; OK, panel opening, magnifier and fullscreen act once on release. A known older stock labwc template lacking explicit volume overrides gets the same fixed volume defaults in the runtime copy; explicit custom bindings are not overwritten.

If recovery is needed, stop the TV service, run `/home/ad-tv/.local/share/ad-linux-tv/venv/bin/ad-linux-tv --config /home/ad-tv/.config/ad-linux-tv/config.yaml clear-tv-shortcuts` as `ad-tv`, then start the service. This removes the optional saved assignments, including a malformed or duplicate assignment subtree, without printing config contents; it does not remove the independent OK defaults or the external hwdb rule. Preserve SSH/console access and back up config before upgrades or downgrades.

run.sh prepares a marked browser.zoom.siteSpecific=false block for effective service views, including inherited common settings and resets. It targets only the dedicated profile and retains original preferences; resetting common settings still needs the block. Full Firefox restart applies this per-tab persistence mode; there is no per-origin fallback. Installed signed0.4.1 has capability-gated HTML/media/view support and the accepted tile-open zoom repair, not physical media qualification. Independent Python/UI/magnifier/discovery updates do not require that signature. Signed 0.4.2 adds `video_fullscreen_v1`; `configure-firefox.sh` sets `full-screen-api.allow-trusted-requests-only=false` and `full-screen-api.warning.timeout=0` in the dedicated profile only, because the bridge's fullscreen request is not a user gesture. The same profile sets `media.autoplay.default=0` so services start playback with sound (KION otherwise starts muted). Signed 0.4.3 also finds media inside shadow roots (VK Video). See [bridge protocol](../../bridge-protocol.md).

The [Android shell](android-remote.md) uses server-hosted UI and isolated profiles. The last delivered native APK is0.2.4 with a TV icon; exact installed phone version is unverified. It retains a compact48dp header, dark picker/manual entry, native-only inset handling and saved-last-center startup through preflight/profile isolation. Notification media buttons require explicit opt-in, disabled by default. Native0.2.5/code6 is now [hosted through the same QR](../../verification/android-apk-download-2026-10-27.md), not proven installed on the phone. The curated fixed APK is root:root0444, single-link, exact size/hash, separate from the app fingerprint. The original0644 publisher failed the actual verifier; a reviewed held-FD metadata-only correction narrowed it to0444 without another app restart. Future atomic publication sets0444; unknown files/links/parents are not modified. The48-runtime-file server initially deployed as91661/build8a; the [iOS invitation update](../../verification/ios-apk-invitation-2026-10-28.md) deploys1a7ff9/buildb879 through a new private ios-apk-ui-app transaction. Both preserve private0700, signed0.4.1, wrapper, curatedAPK0444 and external timer324. Do not replay/delete successful transaction markers. The phone Menu exposes settings/QR rather than service/URL/browser-command banks. Static-only UI updates may replace the owned installed/source assets with backup/hash checks without restarting the TV service; no config/profile/XPI write is needed. Build/unit/lint/fake NSD checks are not phone, actual multicast, WebView or media delivery acceptance. Loading a config never adds discovery; `install.sh` (new install or update) adds an enabled block with a new ID to a config that has none, and leaves an existing block, including a disabled one, unchanged. Without a manual `name` the advertised name is `<short hostname> TV` (fallback `Linux TV`), read at server start; `enable-discovery --discovery-name ''` returns to it. Migration must preserve private config/auth and stable identity.

## Video geometry and UR02 OK

The video-geometry operation requires a separately signed bridge 0.4.4 or later and the current server; an older bridge leaves it unavailable. Bridge 0.4.5 also attempts accessible embedded frames and shadow roots. Its TV failure message uses the existing layer-shell timer script, which must also be updated by the deployment procedure. The separate current-video panel runs as a child of the TV session. If it exits, the phone reports it unavailable until the next session. Both `setup.sh` and the existing-install `deploy.sh` install its session, panel and local client files. Updating these files does not itself start the new panel: the updated server and TV session must be started before use. Plan any session restart with the viewer.

The panel's fixed `/api/local-video-panel` channel is kiosk-only, loopback-only and requires the exact loopback Host, Origin and panel header. Its finite actions do not accept scripts, paths, URLs or media names. Headless Wayland tests use only synthetic content; they and source tests do not establish real-site or physical-TV acceptance. No physical remote button is assigned by this feature.

On the reference TV, a locally administered hwdb rule maps the verified UR02 Keyboard OK scan from `KEY_SELECT` to `KEY_ENTER`; the owner confirmed that OK opens a tile. The rule matches all devices with the same bus/vendor/product IDs, not a Bluetooth address, and is not managed by the app. Verify a target and existing rules before applying it; rollback has not been physically tested. See [troubleshooting](../../troubleshooting.md#ur02-ok-does-not-activate-a-tile).

## Fixed host power boundary
The power delivery installed root-owned `ad-linux-tv-poweroff.service` and one exact `ad-tv` sudoers command to start it. Its fixed two-second grace precedes host poweroff; no arbitrary unit, argument, shell or generic power privilege is granted. Installation/verification never starts or enables the shutdown unit. A phone session+CSRF and expiring one-use confirmation are required even on loopback. Whole-host shutdown stops unrelated tasks too; only the computer's physical button can restart it through this feature.

Display sleep is separate: managed pause and verified silence precede output-off, and wake never resumes playback. Existing optional CEC is directed wake only, not provisioning or physical-TV-state proof. Use the TV remote if the output is on but no picture appears. The [power delivery record](../../verification/remote-power-2026-10-26.md) records backup, wheel digest, preservation checks and outstanding physical gates; no destructive acceptance was run.

## Bluetooth adapter operation

The Bluetooth selector uses the existing user-session BlueZ D-Bus boundary; it does not install drivers, helpers, services or new privileges. Selection does not switch the system default for other applications or migrate bonds. Only a user's explicit power-on request targets the selected controller, and BlueZ may deny it. The dedicated profile's managed `user.js` homepage is the local launcher on Firefox startup; ordinary Home editing is not intercepted. Firefox browser-home navigation may navigate the current tab, not run the bridge's managed Home command. Physical shortcut and button behavior remain unverified; see the [adapter feature](../features/bluetooth-adapter-selection.md).

## Safety, failures, and recovery
Never put PIN/secrets in command arguments or logs; review dry-run before mutation. No silent sudo. Installed CLI validates config; troubleshoot server output, matching bridge localhost port 8765, and shared private LAN. Uninstall retains user configuration.

## Verification boundary and target checklist
Automated source/docs checks alone do not establish target behavior. On the reference TV, HDMI rendering and audible test sound, signed XPI persistence across Firefox restarts, YouTube through Xray, Browser/Home commands, authenticated text entry, site-provided keyboard icons on Yandex and YouTube, Ethernet-to-Wi-Fi address and QR changes, KDE switching, automatic TV-server restart and TV boot after a real HDMI reboot have been observed. Before release, check physical Home/keyboard dismissal, a real phone login/retry lockout/outside access; no-HDMI fallback; a fresh DHCP lease; keyboard symbols and password fields; X11/Wayland navigation as applicable; website audio, login persistence, service playback and DRM without bypasses; signed XPI update/digest flow. See [target checklist](../../target-checklist.md).

## Non-goals and related contracts
No disabling of signature checks or DRM circumvention. The generic per-user installer still opens a supplied XPI for interactive confirmation; only the dedicated kiosk profile enables its signed bridge automatically. Graphical startup applies only in an active graphical user session. Kiosk integration is separately previewed and activated under the [TV session feature](../features/dedicated-tv-session.md); KDE configuration, where present, stays intact.
