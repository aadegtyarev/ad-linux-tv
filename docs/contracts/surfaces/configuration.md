# Surface contract: configuration

## Boundary and consumers
The Python server and `init-config` CLI consume one user configuration file, `~/.config/ad-linux-tv/config.yaml`. It is server-side only; browser clients receive service catalogue and page size, never authentication material.

## Inputs and schema
YAML has required `bind`, `port`, `page_size`, `auth`, `services` and optional `proxy`, `audio`, `pointer`, `discovery`, `magnifier`, `view`. Bind is an IP address; bridge port is fixed at 8765; page size is integer 1–100. `auth` has base64 salt (at least 16 decoded bytes), verifier (32 decoded bytes), and optional boolean `require_pin` (legacy default `true`). New generated configurations explicitly set `require_pin: false`; existing files retain their saved mode. Services is a non-empty list of entries with required `{id,name,url}` and optional `color` (`#RRGGBB`) and `view`: unique lowercase safe IDs (1–32 chars), names 1–80 chars, validated HTTPS service URLs. Initial generated services are VK Видео, КиноПоиск, Яндекс Музыка, YouTube, KION, and Браузер (`https://ya.ru/`), each with a default tile color. Existing configurations without colors remain valid.

`proxy` has `mode: system` or `mode: none`, or `mode: custom` with `protocol: http|socks5`, a hostname/IP and integer port 1–65535. It applies only to the dedicated TV Firefox profile. New configurations select system proxy; an existing Beelink configuration without the field retains its pre-existing local Xray profile until the user changes the setting. Manual proxy keeps localhost/private LAN bypass. Proxy credentials are not accepted.

Optional `audio` contains `browser` and `player` integer levels from 0–100, plus optional boolean `browser_muted` (default `false` for existing files). New configurations write all three fields. These are the saved Firefox stream level and mute targets and accessible page-player level target. Selected output and its volume retain their existing TV-user audio preference. Optional `pointer.acceleration` is an integer 0–100, default 50; zero preserves the former constant cursor mapping. Settings save these fields atomically in the same private config file.

`init-config` generates a random disabled PIN verifier without prompting. Enabling or replacing a four-digit PIN in TV/phone settings writes a PBKDF2-HMAC-SHA256 verifier (310,000 rounds) to config and the code to the existing local-TV-only mode-0600 display file. Keep both files private; never publish or log them. Installer preserves existing configuration; uninstall preserves it.

Optional `discovery` has exactly boolean enabled, canonical UUID id and bounded printable name (1–80 chars/max160 UTF-8 bytes). New init enables a new stable ID; legacy omission stays unchanged/no broadcast. Explicit enable-/disable-discovery preserve ID and auth. The private/direct-Host identity endpoint exposes no auth and returns503 for unconfigured legacy files. Discovery is correlation, not authentication.

Optional `magnifier.scale` is finite1.25–5, quarter steps, default2.5. A scale save is private/atomic and does not actuate; the own kiosk renders a private runtime labwc rc.xml before startup, exporting the applied boot scale. Settings distinguish saved/applied state even across a server-only restart. Only explicit restart interrupts viewing.

Optional root `view` and per-service override `view` accept only mode desktop|mobile and integer zoom50–300. Legacy explicit mode-only views default zoom100/200 respectively; common omission/reset instead means desktop125, derived without rewriting YAML on load. Existing explicit service overrides remain authoritative. Shared collapsed phone/TV «Вид сайтов» selects «Все сайты» or one configured site, saves an explicit override, or removes only that override with «Как для всех сайтов». YAML remains supported. The ordered settings snapshot adds `service_views` with ID/name/optional override/effective view, without URLs/auth data. Existing authenticated/CSRF-protected settings accept strict `service_view` with a configured ID and validated view or null; unknown IDs, extra fields and invalid numeric types fail before mutation.

Saving is targeted, atomic/private, preserves unrelated fields/auth/sessions/other exceptions and never silently navigates, reloads video or restarts. State distinguishes saved values, prepared boot-profile fingerprint, restart need and fresh tab_view_v1 capability. Response generations protect newer drafts and acknowledged state; matching view acknowledgements immediately expose a required explicit restart with truthful apply feedback. Restart when required, then reopen the service. Managed startup derives a marked browser.zoom.siteSpecific=false block in the dedicated TV profile, preserving original lines; inheritance/reset still needs it. This changes that profile's zoom persistence, not personal/default profiles. Signed0.4.1 supports the bounded automatic/per-tab getter-before-setZoom policy, without setZoomSettings or per-origin fallback; legacy0.3.2 cannot apply it. See [tile-open verification](../../verification/tile-open-zoom-2026-10-26.md). No arbitrary UA/header/script input, per-origin fallback, full device emulation or DRM guarantee.

The [2026-10-27 deployment](../../verification/settings-versions-2026-10-27.md) installed S01/S02: six services inherit the saved common desktop125, with no override or pending restart. This supersedes the earlier power-scope mobile200 omission/reset default without rewriting the historical approval. Power/CEC adds no client-supplied command, device path, secret or settings file; private config/auth/profile isolation remains unchanged. Physical acceptance is separate.

## Phone settings presentation
Phone Menu exposes sound/output, PIN/proxy, pointer, magnifier, shared view settings and QR help. The configured-site selector only scopes view editing; it is not a service launcher. Website-address forms and duplicate browser-key/Tab command banks are not added. Legacy command/input endpoints remain unchanged.

## Read-only version metadata
The existing settings snapshot adds optional `server: {version: string, build: string}` without changing authorization, routes or configuration. Version comes from installed distribution metadata; build is a cached16-character SHA-256 fingerprint of shipped Python modules and allowlisted public assets. Relative names/content, not Git, installation paths or mtimes, determine it; config/cookies/profiles are not inputs. Unavailable fields return `unknown` independently; snapshots are defensive copies. Metadata is display information, not authentication, and adds no poll, restart or reload.

The installed server reports0.1.0/build03c898b93f8fee48. Older servers may omit metadata. Android0.2.5/code6 remains an undelivered candidate; the [version-info feature](../features/remote-version-info.md) stays open for native/physical acceptance.

## Outputs and failures
Invalid syntax/schema/field values fail closed with safe, generic or field-specific configuration errors; parser internals and secrets are not propagated. Launcher shows a configuration error rather than service tiles when loading fails. Bridge endpoint port must stay synchronized with extension localhost port 8765. PIN mode/code changes take effect immediately and invalidate all phone sessions. Proxy changes are saved immediately, but Firefox reads them after the user activates the offered TV-session restart. Invalid updates preserve the previous setting.

## Verification and non-goals
Automated config tests validate accepted/rejected schema, persistence, session invalidation and safe errors. Live target checks cover the Settings page and proxy inference without altering the current PIN or proxy. No secrets in client config, URLs, status, or logs.
