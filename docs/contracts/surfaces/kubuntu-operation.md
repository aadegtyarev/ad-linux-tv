# Surface contract: Kubuntu operation

## Boundary and consumers
`install.sh`, `uninstall.sh`, CLI and graphical startup install/run/remove the application within the invoking user's session. Operators use the documented dry-run, install, update and removal flows. Beelink-specific TV integration is staged separately from the existing KDE login.

## Paths and flows
- App, venv and run script: `~/.local/share/ad-linux-tv`. Persistent Firefox Snap profile and signed XPI: `~/snap/firefox/common/`. Configuration: `~/.config/ad-linux-tv/config.yaml`. Optional Plasma autostart: `~/.config/autostart/ad-linux-tv.desktop`.
- `./install.sh --dry-run` is the non-mutating default preview; actual installation requires explicit `./install.sh --install`. `--no-autostart` omits/removes the invoking user's Plasma autostart entry for a separately managed TV session. Installation prompts for PIN, preserves existing config, uses a user venv, does not use sudo by default, and does not edit Firefox profile internals or register extensions unattended.
- `./uninstall.sh --dry-run` previews; `--remove` removes app/autostart and preserves config plus Firefox Snap profile/XPI. Update is backup config then rerun install.
- Release extension flow requires signed XPI and SHA256 supplied via `AD_LINUX_TV_XPI_URL` and `AD_LINUX_TV_XPI_SHA256`; installer verifies digest and opens XPI for explicit interactive Firefox confirmation. Current AMO signing/assets are not provided. Optional enterprise policy is a separate explicitly privileged target gate, not default installation.
- In the Beelink kiosk, labwc, Squeekboard and a small GTK layer-shell touch overlay run Firefox in a maximized window with a dedicated Snap profile. Two upper-right controls offer Home and a keyboard toggle on third-party pages, and hide when a window is fullscreen or no touchscreen is connected. The TV profile hides Firefox browser chrome, while the phone remote can open a managed Browser tab and enter a direct HTTP(S) address. Home shows phone QR/address and the PIN read from a private file only by the local kiosk; a small System control opens the confirmed KDE switch. A separate root-owned systemd unit performs the switch; `ad-tv` may only request that exact unit through sudo. Console and SSH `gui` recovery remain available. The kiosk unit restarts the whole session after an unexpected browser/server exit, with a bounded systemd start limit.
- On this Beelink, the dedicated Firefox profile uses local Xray `127.0.0.1:1081` for external sites and bypasses the proxy for localhost/private LAN. `ops/beelink/configure-firefox.sh` manages only that profile. KDE's Firefox profile is not changed. `ops/beelink/select-audio.sh` prefers an HDMI sink when present; the user's WirePlumber state retains the selection across TV session restarts. The phone remote can inject authenticated text through labwc's virtual keyboard protocol without changing signed-XPI permissions.

## Safety, failures, and recovery
Never put PIN/secrets in command arguments or logs; review dry-run before mutation. No silent sudo. Installed CLI validates config; troubleshoot server output, matching bridge localhost port 8765, and shared private LAN. Uninstall retains user configuration.

## Verification boundary and target checklist
Automated source/docs checks alone do not establish target behavior. On Beelink, HDMI rendering and audible test sound, signed XPI persistence across Firefox restarts, YouTube through Xray, Browser/Home commands, authenticated text entry, site-provided keyboard icons on Yandex and YouTube, Ethernet-to-Wi-Fi address and QR changes, KDE switching, automatic TV-server restart and TV boot after a real HDMI reboot have been observed. Before release, check physical Home/keyboard dismissal, a real phone login/retry lockout/outside access; no-HDMI fallback; a fresh DHCP lease; keyboard symbols and password fields; X11/Wayland navigation as applicable; website audio, login persistence, service playback and DRM without bypasses; signed XPI update/digest flow. See [target checklist](../../target-checklist.md).

## Non-goals and related contracts
No unattended Firefox registration, disabling signature checks, or DRM circumvention. Graphical startup applies only in an active graphical user session. Beelink system integration is separately previewed and activated under the [TV session feature](../features/beelink-tv-session.md), leaving KDE configuration intact.
