# Surface contract: Android media-center remote

## Boundary and flow
The Kotlin shell discovers/selects a server and loads its actual `/remote` page in a WebView. It is not a packaged cross-origin replacement UI. Android 9+ and a WebView supporting public AndroidX WebKit MULTI_PROFILE are required; unsupported providers fail closed with an update explanation.

NSD `_ad-linux-tv._tcp`, manual private address and QR provide candidate endpoints, not authentication. A cookie-free `/api/device` read validates app/protocol/path/port/canonical UUID and bounds. Hostnames resolve to private numeric addresses; redirects, URL credentials/query/fragment and unsupported schemes/paths are rejected at entry. The user explicitly selects a center and authorizes its web remote under the existing PIN/session rules.

Saved preferences contain at most 64 nonsecret ID/name/origin records and last ID. Profiles are keyed by ID plus origin. Selection increments a generation; switching retires the native media client, disposes the old page and clears buffered gestures/queued keys/clicks. Already-dispatched old operations may finish only on their old target, never replayed or redirected onto the new one. On cold start the saved last ID+origin is attempted once through cookie-free preflight and profile-before-load. Missing/forgotten records or failed preflight return to the picker without retries or another-center fallback; an explicitly open picker/failure intent survives recreation. No automatic selection of another center occurs on loss. Same-ID new origins require explicit confirmation, fresh preflight and their own profile authorization; ambiguous discovered IDs are not selected. Removing a favorite is not session revocation.

## Compact chrome and media
Current server-hosted0.2.5/code6, following delivered0.2.4, uses one 48dp native header containing the selected name, «Сменить медиацентр» and a compact settings gear. A separate status paragraph appears only while choosing/connecting or reporting an error, not above the healthy remote. Playback controls normally live inside the server's remote page. Notification media buttons are disabled by default and require explicit opt-in. Android 13+ requests notification permission only after that opt-in; OS-wide notification disablement and a blocked media channel are respected on all versions and reported without repeated permission prompts or overriding system settings. A media connection starts only while foreground with the freshly shown, selected target and loaded page; a live connection already owned by that target/epoch is reused on resume.

The native media service/client uses its selected-profile CookieManager, Origin/CSRF, capability, epoch/media-identity and stale-owner guards; cookies are not exported into JS/preferences/logs and uncertain actions are not retried. Opted-in connections can be stopped from their notification or by switching. A current owner whose connection startup fails receives a fixed generic error toast; stale/rejected owners receive no failure feedback, and the service then cleans up. There is no local playback, microphone access or boot autostart. MainActivity remains single-task.

The picker/manual-entry UI uses the remote's dark blue/cyan palette, rounded controls and separate name/address/status hierarchy. The picker hides redundant switching chrome while retaining address/QR/search. The0.2.4 adaptive icon uses an opaque dark background and a centered TV glyph inside the mask safe zone. Delivery is not proof of icon appearance on every launcher/mask, nor of the exact APK installed on the phone. Native0.2.2 inset improvement was operator-confirmed; all phone/layout/lifecycle cases are not thereby qualified. Native root handles system bars/IME once, without duplicating WebView safe-area insets; standalone browsers retain their own safe-area behavior.

## Security and limits
WebView uses real separate profiles, no general JS bridge, file/content/universal file access, third-party cookies or SSL-error bypass. Selected-origin navigation/initial resource requests are constrained; the trusted server's same-origin security policy remains necessary. Fixed trusted lifecycle JS only suspends the remote. Native HTTP redirects are disabled. Native network calls/body sizes/worker queues are bounded; OS hostname resolution can still take time.

HTTP LAN traffic is unencrypted. A UUID, private IP or preflight is not peer authentication and cannot prevent a malicious LAN endpoint from receiving cookies or impersonating identity. Optional device binding on session/login/WS protects accidental different-ID reassignment, not MITM. Do not port-forward or use an untrusted shared network. HTTPS uses normal system trust; the installer provisions no TLS.

Native controls use density-independent hit areas and scalable text. The web page restores its original compact, mostly pixel-sized typography and proportions instead of the rejected rem/container redesign. WebView retains its font-size preference and user zoom is not disabled, but this is not a claim that every fixed-size label follows Android font scaling. Short screens may scroll. System bars/cutouts/keyboard insets are handled; physical appearance and lifecycle behavior still require phone acceptance.

## Public app metadata (S02 candidate)
Published 0.2.5/code6 preserves the prior TV glyph, compact header, insets and notification opt-in. After a trusted selected-origin `/remote` page finishes, native code supplies only immutable public `window.adLinuxTvAppInfo = {version: string, build: integer}` from runtime PackageInfo. Current selection, page identity, lookup generation and callback/current URL equality fence injection; stale callbacks cannot supply metadata to a newly selected page. The fixed escaped script is bounded and idempotent, with no callable bridge, new permissions or cookie export. Unavailable metadata uses `unknown`/0, rendered as unknown by the shared settings UI. This display constant is not authentication and a trusted page may prepopulate it. The [same-QR delivery](../../verification/android-apk-download-2026-10-27.md) hosts this exact APK for explicit normal-browser download/install; exact phone installation and data-preserving upgrade remain unverified. The QR/native preflight/profile flow is unchanged. Device-bound Android pages suppress the APK link even when old/late app metadata is absent and direct users to the normal camera/browser. Recognized standalone iPhone/iPad/iPod browsers hide Android invitations/guidance and keep the web remote; this local presentation heuristic does not change Android binding/profile/metadata or authenticate a platform. See the [iOS update verification](../../verification/ios-apk-invitation-2026-10-28.md).

S02 is an offline candidate, not installed. Actual WebView callback/current-URL strings with the device fragment and phone lifecycle remain physical acceptance limits; JVM tests do not establish them. The [feature contract](../features/remote-version-info.md) remains open.

## Verification and related surfaces
JVM policy tests and Robolectric fake-NSD/virtual-Looper tests cover selection, origin/profile naming, ambiguity, stale resolution, loss/re-found, stalls, bounded serial resolution and stale-service-owner decisions. Build/lint and synthetic offline web layout are not proof of actual multicast, WebView isolation implementation, notification/FGS delivery, camera, gesture or phone behavior. Physical acceptance remains in the [target checklist](../../target-checklist.md). Operator-reported shade controls work with VK; KION's missing controls have no established cause. Neither that observation nor source mute/pinning audits qualify universal media support or establish an audio fix.
