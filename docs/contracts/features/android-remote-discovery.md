## Interfaces and scenarios
- Server advertises actual eligible bound LAN service/8765, human name, persistent random nonsecret device ID, protocol version and remote path. Service settings belong in the existing single config.yaml; preserve legacy configs. No PIN/token/verifier/typed text in DNS-SD, identity metadata, URLs, logs or APK config. Stop/unregister own announcement on server close; discovery failure must be visible/diagnosable without breaking legacy browser remote. No system Avahi/service/firewall changes or live network scan in development tests.
- Android uses NsdManager and bounds/validates discovered identities/addresses/ports/paths. Discovery is untrusted and does not authorize control; existing PIN/session/Origin/CSRF/private-source checks remain. No TLS/Internet-security claim for trusted-LAN HTTP. Require explicit first selection/pairing, never silently select a different device after loss. Stable ID is correlation, not authentication or cryptographic anti-spoofing.
- List discovered and saved devices with friendly names; persist nonsecret identity/address/last-selected selection. Rediscover same saved ID after IP changes. Manual private-LAN HTTP(S) address and QR path supported, with cancellation/invalid/foreign URL refusal. Support multiple devices with genuinely isolated WebView authentication/cookie/storage per device, including same IP at different times or ports. Do not export HttpOnly cookies to JS, weaken server security, or leak cookies during discovery/redirects. If safe platform profile isolation is unavailable, fail closed with actionable explanation rather than cross-device cookie reuse.
- Reuse server-hosted `/remote` UI and assets in WebView, same origin; no arbitrary native JS bridge or file:// universal access. Navigation/subresources/redirect/HTTP cleartext scope must be constrained to selected validated origin, HTTPS certificate errors refused, no mixed-origin cookie exposure. INTERNET/NSD/local-network/camera permissions only as needed, with denied/unavailable cases handled. Avoid microphone/speaker permissions.
- Switching through «Сменить медиацентр» must not restart Android UI app: revoke old intent/generation, close/destroy old page/WebSocket, clear pending requests/gestures/held keys, fence late callbacks/NSD results, then open chosen center in its own isolated auth profile. No replay of old actions to old/new center. Background/recreate/connection loss must not produce queued input or implicit cross-center selection. Existing web browser behavior remains compatible; no unauthenticated lifecycle control API.
